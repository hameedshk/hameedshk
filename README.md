## Why IAM × AI

AI agents are only useful when they can act, and they're only safe to act when identity is done right.

- **Agents need identity.** An agent acting for a user should never be able to do more than that user can. I design agent actions scoped to the user's own permissions.
- **Identity needs AI.** IAM is full of repetitive questions and small requests. Agents can answer them *and* complete them, turning helpdesk tickets into self-service.
- **Both need policy.** Fine-grained, policy-based access (RBAC, ABAC, PBAC) is the guardrail for people and agents alike.

## Agentic AI

**An IAM assistant that answers *and* acts.** Took it from a helpdesk-overload hypothesis to user acceptance testing: analysed a year of IAM incidents, ranked use cases by impact, and built an assistant that completes requests across accounts, access, credentials, roles, scopes and connectors, within each user's own permissions.

**Built on:** retrieval-augmented generation (RAG) and tool-calling agents with LangGraph on AWS Bedrock.

**Released behind guardrails.** RAGAS-based evaluation with release gates for first-contact resolution, task completion and hallucination. Reached 80% first-contact resolution in UAT.

**AI-assisted delivery.** Using AI coding agents to speed up how my team builds identity platforms.
